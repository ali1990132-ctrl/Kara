# بوت كارة ستور — WhatsApp Cloud API

مشروع بداية (starter) لبوت واتساب الرسمي من Meta. يحتوي على قائمة الاشتراك، اختيار الباقة والمدة، طرق الدفع، واستقبال إشعار بصورة الوصل للمراجعة اليدوية.

## الأسعار المضمّنة
- الشبابي: شهر 10,000؛ 3 أشهر 25,000؛ 6 أشهر 40,000؛ سنة 60,000 د.ع.
- العائلي: شهر 5,000؛ 3 أشهر 10,000؛ 6 أشهر 15,000؛ سنة 25,000 د.ع.
- ماستر الرافدين: 9769867020
- زين كاش ورصيد آسيا: 07711608207

## تنبيه مهم
هذا مشروع برمجي جاهز للتجهيز، لكنه **ليس مفعّلاً أو مستضافاً أو مربوطاً بحساب Meta تلقائياً**. لا توجد طريقة آمنة لتفعيل Cloud API على حسابك من دون موافقتك وخطوات الدخول/الربط داخل Meta. لا تضع كلمات المرور أو رموز التحقق في المحادثة.

## المتطلبات
- Node.js 20+
- استضافة عامة تدعم HTTPS (مثل خدمة استضافة تطبيقات Node)
- حساب Meta for Developers
- منتج WhatsApp مضاف إلى تطبيق Meta
- رقم اختبار Meta أولاً
- Webhook callback URL عام مثل `https://YOUR-DOMAIN/webhook`

## التشغيل محلياً
1. ثبّت Node.js 20 أو أحدث.
2. فك ضغط المشروع وافتح مجلده في الطرفية.
3. نفّذ:
   ```bash
   npm install
   cp .env.example .env
   ```
4. افتح `.env` وأدخل القيم من لوحة WhatsApp API Setup في Meta. اترك `ADMIN_PHONE` فارغاً بالبداية أو استخدم مستلماً تجريبياً فقط.
5. شغّل:
   ```bash
   npm start
   ```
6. اختبر `http://localhost:3000/health`. هذا الفحص محلي فقط؛ Meta لا يمكنه الوصول إلى localhost.

## إعداد Meta الآمن
1. سجّل الدخول إلى Meta for Developers وافتح My Apps > Create App.
2. أضف WhatsApp كمنتج، ثم افتح WhatsApp > API Setup / Quickstart.
3. استخدم رقم الاختبار الذي توفره Meta. أضف رقمك كمستلم اختبار فقط إذا طلبت لوحة Meta ذلك؛ هذا لا يسجل رقمك الحالي كمرسل API.
4. انشر الخادم على استضافة HTTPS، ثم عيّن Callback URL إلى `https://YOUR-DOMAIN/webhook`.
5. اختر Verify Token يطابق قيمة `VERIFY_TOKEN` في `.env`، ثم اضغط Verify and Save.
6. اشترك في حقل Webhook `messages`.
7. استخدم رمز الوصول الذي توفره Meta للاختبار. رموز الاختبار قد تكون قصيرة العمر؛ قبل الإنتاج تحتاج رمزاً دائماً/نظامياً وصلاحيات وحساب أعمال مناسبين.
8. جرّب الرسائل من رقم الاختبار أولاً، وتأكد من وصول التنبيه التجريبي إلى مستلم الاختبار.
9. **لا تضف رقم كارة ستور الحالي كرقم API ولا تحذف واتساب بزنس.** قبل ذلك، تحقّق داخل Meta من توفر مسار رسمي مناسب لحسابك (مثل Coexistence إن كان متاحاً ومؤهلاً) أو خطّة نقل موثقة مع نسخة احتياطية. الأهلية تختلف ولا يضمن هذا المشروع بقاء الحساب في التطبيق مع API.

## إعداد متغيرات البيئة
انسخ `.env.example` إلى `.env` وأكمل:
- `VERIFY_TOKEN`: سلسلة سرية من اختيارك، ليست رمز Meta.
- `WHATSAPP_TOKEN`: رمز الوصول من Meta.
- `PHONE_NUMBER_ID`: معرّف رقم الاختبار في لوحة Meta، وليس رقم الهاتف.
- `WABA_ID`: معرّف حساب WhatsApp Business (قد لا يحتاجه هذا الإصدار).
- `GRAPH_API_VERSION`: استخدم نسخة Graph API المدعومة الظاهرة في لوحة Meta وقت الإعداد.
- `ADMIN_PHONE`: رقم مستلم إشعارات الإدارة بصيغة دولية، أرقام فقط. في البداية استخدم مستلماً اختبارياً فقط.

## حدود النسخة الحالية
- حالة الطلبات محفوظة بالذاكرة فقط؛ إعادة تشغيل الخادم تمسح الجلسات. يلزم قاعدة بيانات دائمة قبل الاستخدام التجاري.
- يستقبل صورة الوصل ويُرسل معرّف الوسائط إلى المشرف، لكنه لا ينزّل الصورة تلقائياً. مراجعة الدفع يدوية.
- لا يوجد تفعيل آلي للاشتراك، ولا لوحة إدارة للمشتركين حتى الآن.
- رسائل WhatsApp API تخضع لسياسات Meta ونافذة خدمة العملاء وقواعد القوالب؛ قد يلزم قالب معتمد للرسائل التي يبدأها النشاط التجاري خارج النافذة.
- لا تضع رموز API أو بيانات حساسة في GitHub عام أو صور الشاشة.
- استخدم المشروع للطلبات المشروعة فقط، وراجع شروط Meta الحالية قبل الإطلاق.

## الملفات
- `src/server.js`: webhook ومنطق المحادثة.
- `public/index.html`: معاينة الأسعار.
- `.env.example`: أسماء إعدادات البيئة دون أسرار.
